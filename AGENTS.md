- Distinguish project-independent engine probes from project-affecting engine operations: fixed probes (`--version`/`--help`/`--dump-extension-api`) never open, import, or run a project and never need a project scaffold. Solaris does not open, import, execute, or run a project at this stage. `--path`/`--upwards`/`--import`/`--scene`/`--script` (and `--editor`) are prohibited in fixed-probe invocation code by the architecture check; `--path` is allowed only in the recovery runner module with the `--editor`/`--headless`/`--recovery-mode` pairing, and recovery execution is unavailable anyway; a `godot` binary must be on `PATH` (or configured as a trusted installation) before anything engine-related runs.
- Engine probes stay project-independent and read-only: Solaris never opens, imports, or runs a project at this stage.
- Recovery-mode probing is contracts + static preparation + approval machinery + truthful reporting; the disposable mirror and the recovery runner are fail-closed no-ops (typed `unavailable`, zero filesystem operations, never spawn). Do not restore check-then-create/check-then-delete mirror logic, do not present the mirror/launch as shipped, and never claim the live isolation probe passed while execution is unavailable.
