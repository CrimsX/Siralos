## Gotchas

- Distinguish project-independent engine probes from project-affecting engine operations: fixed probes (`--version`/`--help`/`--dump-extension-api`) never open, import, or run a project and never need a project scaffold. Solaris does not open, import, execute, or run a project at this stage. `--path`/`--upwards`/`--import`/`--scene`/`--script` (and `--editor`) are prohibited in fixed-probe invocation code by the architecture check; `--path` is allowed only in the recovery runner module with the `--editor`/`--headless`/`--recovery-mode` pairing, and recovery execution is unavailable anyway; a `godot` binary must be on `PATH` (or configured as a trusted installation) before anything engine-related runs.
- Engine probes stay project-independent and read-only: Solaris never opens, imports, or runs a project at this stage.
- Recovery-mode probing is contracts + static preparation + approval machinery + truthful reporting; the disposable mirror and the recovery runner are fail-closed no-ops (typed `unavailable`, zero filesystem operations, never spawn). Do not restore check-then-create/check-then-delete mirror logic, do not present the mirror/launch as shipped, and never claim the live isolation probe passed while execution is unavailable.
- The bounded Godot GDScript LSP surface (ADR 0011) is contracts + transport + normalization + static preparation + truthful reporting: the LSP runner never spawns the editor, no mirror is created, no port is opened, and no approval is requested while session startup is unavailable; `--lsp-port` is legitimate only inside the LSP runner structurally paired with `--headless --editor --recovery-mode --path <disposable-mirror>` (architecture-enforced); sockets are allowed only inside the approved LSP and sandbox adapters; `workspace/applyEdit`/`workspace/executeCommand` are never implemented; the live isolation probe is reported skipped, never passed. Do not present session startup as shipped, and do not restore port/mirror/process machinery that cannot be identity-bound.
- Version-matched API knowledge and GDScript diagnostics (ADR 0010) follow the same fail-closed posture: the `--dump-extension-api-with-docs` runner and the `--headless --path <disposable-mirror> --script <mirror-script> --check-only` runner never spawn and return typed `unavailable`; the knowledge cache is an explicitly unavailable no-op (never initialized, created, read, or written); no approval for knowledge generation or diagnostics is ever requested while execution is unavailable; nothing is created or deleted. `--script` is legitimate only inside the check-only runner structurally paired with `--check-only` (architecture-enforced); the source workspace never becomes the diagnostic `--path`. A script parse failure would be a valid `checked` diagnostic result, never an infrastructure failure. Do not present generation/check-only execution as shipped, and do not restore cache or mirror storage that cannot be identity-bound. The Godot integration state line must now also cover the language-session surface (ADR 0011) as fail-closed.
- Do not add real provider integrations, persistence, multi-agent functionality, or `/evolve` while the foundation stage is unfinished.
- Security boundaries are mechanically enforced, not documented: do not solve a security finding with docs, comments, naming, UI text, or mock-only tests. Approval `ask` never executes without the exact one-time protocol; the mutation commit machinery (revalidation immediately before the irreversible commit point, identity-bound quarantine displacement with an absence-preserving primitive) is tested internal code that fails closed as `unavailable` at this stage and must not be presented as a shipped capability; the terminal sanitizer is the single output boundary; the input queue is the single terminal read owner.
