# AGENTS.md

## Current state

- npm TypeScript workspace monorepo (npm workspaces, ESM, strict TypeScript, project references).
- `@solaris/core`: application + provider port + tool contracts and bounded tool loop (strict provider stream protocol with cumulative per-turn byte limits, tool-round accounting, transcript pairing invariants) + security model (capability policy, sandbox profiles, backend port, one-time approval port with digest binding) + Godot contracts (installation/version/edition/profile/project models, probe and inspector ports, release-channel/support classification, deterministic selection policy, compatibility assessment, immutable limits). `@solaris/adapters`: deterministic fake provider (with read, write, git, command, and Godot inspection scenarios), read-only workspace tools (`workspace.list`, `workspace.read`, `workspace.search` — the search has independent global traversal bounds), the workspace-mutation surface (`workspace.create_file`, `workspace.edit_file`, `workspace.delete_file`, `/undo`) as unavailable entry points that fail closed as `unavailable` before any write, approval, or checkpoint because Node offers no directory-relative (openat/renameat) primitive and a same-user process can swap a parent or target at any instruction boundary; the former preview/approval/application logic was largely deleted, and what remains is the core contracts (prepared-command/digest/approval ports), reusable tested primitives (path validation, diffing, hashing, the lock, safe-replacement helpers), and the filesystem checkpoint store with its startup reconciliation — automatic checkpoint-retention pruning is disabled: storage pressure fails closed with a typed storage-limit refusal and deletes nothing; the byte limit measures actual regular-file bytes beneath the checkpoint directory including metadata and preimages (allocation overhead is outside the logical byte limit), the proposed checkpoint's exact serialized metadata and preimage bytes are counted before any write, declared preimages are content-verified through a shared handle-bound bounded verifier whose explicit-offset read loop (a short read is never treated as EOF) requires the exact read bytes to match the metadata byte length and SHA-256, with the opened handle and pathname identity proven against the pre-open lstat snapshot and a pre-read/final stability snapshot (identity, size, mtimeNs, ctimeNs) captured from the handle before reading and re-verified after it (a same-size corrupted preimage, a same-content hard-link/rename/symlink/junction substitution, or a same-inode in-place rewrite during verification makes capacity unverifiable; `O_NOFOLLOW` on POSIX, identity/stability comparison on Windows, unusable identity or stability fields fail closed), preimage limits are capped at 64 MiB with larger configurations rejected at store creation, checkpoint operations are bound to their before/after existence states (create: absent→present; update: present→present; delete: present→absent) by one shared validator for prepared and stored records, and any checkpoint whose metadata or preimage cannot be fully inspected (missing, unreadable, invalid, oversized, linked, or size-inconsistent) — or any content beyond the exact metadata.json/preimage.bin layout (unknown files, nested directories, temporary files, links, special files) — makes capacity unverifiable and blocks new checkpoint creation, with unexpected content never repaired or deleted; existing checkpoints are preserved, and no checkpoint is ever deleted at this stage — the identity-bound commit design (commit-time revalidation, digest-bound approval, quarantine displacement with an absence-preserving primitive, parent-chain identity verification before every create) is documented as future work but not offered, no approval for mutations is ever requested, and no new checkpoint is ever created at this stage (historical checkpoint data from earlier sessions, if any, may still be listed). Sandboxed command runners (both `node-script` and `npm-script` fail closed as unavailable under the pinned runtime — the pinned Node runtime cannot mechanically bind execution to the approved script bytes, because the script can reach internal surfaces such as `process.binding` (e.g. `spawn_sync`) to spawn an unconstrained interpreter and the staged private copy can be substituted by a same-user process in the verify-to-launch window; `isAvailable()` returns false for both runners, so no validation command can execute at this stage). Private run-directory creation and cleanup are also unavailable (fail closed) at this stage: Node offers no directory-relative or delete-by-handle primitive, so a same-user process could substitute a verified parent between identity verification and a pathname-based create, and cleanup could delete a substituted object — nothing is ever created or deleted. The Anthropic Sandbox Runtime backend (pinned `0.0.70`) has an enforced host-read allowlist (deny-root on Linux/macOS; on Windows the backend is never reported generally available — setup and host-read capability are separate conditions — and process execution is refused), a fully serialized global sandbox lifecycle, and Godot discovery/static project inspection (fixed-name PATH discovery, canonicalization and SHA-256 fingerprinting with full-hash revalidation, bounded static project scanner and executable-content inventory with project-controlled path containment, `godot.inspect_engine`/`godot.inspect_project` tools). Sandboxed Git inspection is unavailable at this stage: the adapter never spawns Git itself (architecture-enforced), Git could only ever execute inside an enforcing sandbox backend with command-line overrides as defense in depth (repository-selected helpers such as clean filters are not disabled from the command line — their containment is the sandbox boundary alone), and the adapter requires verified Solaris-owned private run directories for every invocation, which fail closed as unavailable. Godot engine probing is intentionally unavailable: the probe runner reports `unavailable` and never spawns the executable, because the backend re-opens the staged copy's pathname at spawn time and a same-user process can substitute bytes between final verification and launch (no exec-by-handle primitive); no engine profile can be produced, and the engine-profile cache is an explicitly unavailable no-op component — it is never initialized, created, read, or written (`load()` is always a miss, `store()` returns a typed unavailable result, `count()` is 0, and the doctor reports it disabled) — so `godot.inspect_engine` cannot return a profile. `@solaris/cli`: interactive terminal with `/help`, `/status`, `/clear`, `/tools`, `/sandbox`, `/permissions`, `/git-status`, `/diff`, `/checkpoints`, `/undo`, `/commands`, `/cancel`, `/godot`, `/godot-installations`, `/godot-project`, `/godot-doctor`, `/exit`, an interactive approval reviewer backed by a cancellable input queue, a single terminal-output sanitization boundary, plus `--sandbox-doctor` and `--godot-doctor` with trustworthy exit codes and `--godot-path`/`--godot-installation` selection overrides.
- Workspace root is the canonicalized launch directory; all tool paths are contained within it. Sandbox config is user-level (`~/.solaris/config.json`). Write tools, commands, and run-directory operations fail closed as `unavailable` before any write, approval, or checkpoint — no approval for mutations or commands is ever requested at this stage, and nothing executes or is created or deleted.
- Godot integration is at the read-only inspection stage (Stage 2 milestone 1 of 6): engine discovery, static project profiling, and compatibility assessment work without opening, importing, or running a project — engine probing (exact version/capability/API profiling) is intentionally unavailable at this stage (the probe runner reports unavailable and never spawns the executable), so no engine profile can be produced, and Solaris does not open, import, execute, or run a project at this stage (recovery-mode project probing is not implemented). Real provider integrations, multi-agent functionality, and `/evolve` are not started.

## Verify

- `npm run check` — full non-mutating validation: format check, lint, typecheck, tests, architecture check.
- `npm run test:sandbox` — live sandbox conformance probes (loudly skips when the backend is unavailable or cannot enforce the host-read allowlist, e.g. Windows without the one-time `npx sandbox-runtime windows-install` setup); skipped or unavailable is never treated as passed.
- `npm run test:godot` — opt-in live Godot probe conformance via `SOLARIS_TEST_GODOT="<absolute-path>" npm run test:godot` (skips loudly when unset).
- `npm run solaris` — build and launch the interactive CLI.
- `npm run check:architecture` — workspace dependency-boundary enforcement via structural TypeScript parsing plus regex/text checks; a developer guardrail, not an OS security boundary.

## Gotchas

- Distinguish project-independent engine probes from project-affecting engine operations: fixed probes (`--version`/`--help`/`--dump-extension-api`) never open, import, or run a project and never need a project scaffold. Solaris does not open, import, execute, or run a project at this stage. `--path`/`--upwards`/`--import`/`--scene`/`--script` (and `--editor`) are prohibited in fixed-probe invocation code by the architecture check; a `godot` binary must be on `PATH` (or configured as a trusted installation) before anything engine-related runs.
- Engine probes stay project-independent and read-only: Solaris never opens, imports, or runs a project at this stage.
- Do not add real provider integrations, persistence, multi-agent functionality, or `/evolve` while the foundation stage is unfinished.
- Security boundaries are mechanically enforced, not documented: do not solve a security finding with docs, comments, naming, UI text, or mock-only tests. Approval `ask` never executes without the exact one-time protocol; the mutation commit machinery (revalidation immediately before the irreversible commit point, identity-bound quarantine displacement with an absence-preserving primitive) is tested internal code that fails closed as `unavailable` at this stage and must not be presented as a shipped capability; the terminal sanitizer is the single output boundary; the input queue is the single terminal read owner.
