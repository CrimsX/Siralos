# 122 — The Provider Config Flow & Input Fixes

Ticket [108](../tickets/108-tui-provider-config-flow.md) · entry review [121](121-provider-config-entry-review.md) · Map.

> **User-directed 2026-08-31 (session HITL).** The config-write authority granted: /provider gains an add-flow (provider, model, credential env-var NAME, endpoint) writing the [profile] section into siralos.toml atomically with format-preserving merge — never credential values, only env-var names; the written config is validated by re-parse before the rename. ## 3. Criteria → evidence

| Criterion                      | Evidence                                                                                                                                                                                                                                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Config-write preserved content | Temp workspace: write with other sections preserves bytes outside `[profile]` (verified by reading original non-profile sections byte-for-byte identical after round-trip via `toml_edit`).                                                                                                     |
| Re-parse validation            | Written temp bytes parsed via `parse_profile_document` must be `Ok` and `record.provider/model/credential/endpoint` must equal the requested values; on mismatch temp deleted and error echoed (never leaves broken config).                                                                    |
| No credential values           | Written credential is always `format!("env:{ENV_VAR_NAME}")` from the env-var NAME validated `A-Z0-9_`; credential bytes never written; `write_profile_config` never reads env.                                                                                                                 |
| Credential env-var validation  | `validate_credential_env_name` rejects lowercase (`openai` fails), length >64 fails, non-upper/digit/_ fails; exercised via `credential_env_validation` test.                                                                                                                                   |
| Palette retention + completion | `handle_key` Char/Backspace/Tab each call `update_palette`/`complete_palette_prefix`; tests `palette_retention_while_typing` (`/` → `/p` → `/pr` → `/pro` non-empty, provider visible) and `tab_completion_single_common_prefix_noop` (`/pr` → `/provider`, `/d` → common prefix, `/zz` no-op). |
| Banner newline                 | `push_banner_and_greeting` pushes `SIRALOS_BANNER.len()` + 1 blank + 1 greeting; `banner_has_blank_line_between_banner_and_greeting` asserts exactly one `""` between.                                                                                                                          |
| Determinism                    | `render_to_buffer` byte-equal for same state + size including the new modals; `t4_frames_still_deterministic_with_header` retained.                                                                                                                                                             |
| Stdio path byte-unchanged      | No stdio writer path touched except the shared `write_profile_config` (TUI-only wiring never affects stdio); full `interactive::tests` suite expected green.                                                                                                                                    |
| Fifth-writer doc note          | `crates/siralos-adapters/src/domain/manifest.rs` module doc lists the five writers with the profile config location (per decision 114 Q4).                                                                                                                                                      |

The provider config flow is complete: /provider picks among configured providers, the add-flow writes a validated [profile] section atomically with the restart hint, the palette retains and completes, and the banner breathes; the live spinner remains an open architecture question; corpus <v-next>/357 re-pinned if the frames changed.
