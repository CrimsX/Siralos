# 89 — The Scheduler-Semantics Re-Pin

Governing plan 68 · entry review [79](79-context-management-foundations.md) · Map.

> **User-directed 2026-08-31 (session HITL).** The four externally-suggested scheduler amendments are adopted as a re-pin of the decision 81 rules: the demand edge (host-owned events, tools stay read-only), digest-counted budget accounting, the pinned-HOT quota with stale-never-promote, and tick coalescing. The frozen clauses hold — deterministic synchronous integer scoring, demotion never deletes — and the decision 84 precondition gate is untouched.

## 2. Amendments to the decision 81 rules

| Amendment                          | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1 Demand edge                     | `TickInput` gains `events: Vec<AccessEvent>` (≤64 canonical). Canonical form: dedupe by `node_id` (one per node), order by `node_id` ascending, truncate to the first 64. Each event's node gets `recency = now` (deterministic clock) and `relevance += 32` saturating at 100. Events may target any tier.                                                                                                                                                                                                                              |
| A2 Digest budget                   | The 4096-token budget counts UNIQUE content digests, not nodes. Among HOT nodes, a digest's tokens count once at its first node in canonical node ordering; subsequent same-digest HOT nodes contribute 0. Demotion rule otherwise unchanged: demote lowest-scored HOT non-pinned first (tie `score` asc, `node_id` asc) until unique-digest total ≤4096.                                                                                                                                                                                |
| A3 Pin quota + stale-never-promote | (a) Pinned-HOT tokens capped at 1024 (unique-digest accounting). If pinned HOT total >1024, demote lowest-scored pinned HOT nodes to WARM (`node_id` asc tiebreak) until ≤1024. Pin still protects within quota, and the general 4096 demotion still skips pinned nodes. (b) A STALE node is never promoted by any rule — demand events may update a stale node's `recency`/`relevance`, but the promotion gate refuses stale nodes. Existing `stale demotes regardless of pin` is unchanged.                                            |
| A4 Tick coalescing                 | A tick whose input is a no-op — empty events AND no graph deltas since the last processed tick (compare the input's `graph_revision`/`new-node` set) — produces the identical output state without re-running the pipeline. Deterministic; derived from input values only (purity preserved).                                                                                                                                                                                                                                            |
| Processing order (pinned)          | 1) coalescing guard; 2) stale demotion (existing, any tier, regardless of pin); 3) demand-edge score updates; 4) recompute scores; 5) promotion gate (stale never promotes); 6) pin-quota enforcement; 7) budget enforcement (unique-digest).                                                                                                                                                                                                                                                                                            |
| Seam rules                         | The demand edge is HOST-OWNED: events are derived from tool RESULTS at the host-owned seam (a pure adapters-side helper that derives `AccessEvents` from a tool call + result — query terms/hit node ids), never inside the pure tool functions, never in `ContextToolState`, never model-supplied. Tools remain read-only over immutable snapshots. Live registration stays precondition-gated (decision 84 untouched): the demand edge is proven at the core/adapters seams with tests; no CLI live wiring beyond what already exists. |
| Frozen guard                       | The context-benchmark record (corpus v65, decision 88) must remain BYTE-IDENTICAL — the benchmark flow passes no events and its scheduler path must be untouched. If the benchmark output changes, treat it as a scope defect and fix the scheduler change, never the benchmark.                                                                                                                                                                                                                                                         |
