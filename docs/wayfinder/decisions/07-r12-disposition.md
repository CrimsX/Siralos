## Summary

Per **ADR 0032** the TypeScript implementation is the **behavioral reference implementation** — the migration oracle. The Rust candidate is the **successor implementation**. Behavioural parity does not require structural parity, but retirement requires **measured parity**: The TypeScript implementation is retired only by later Stage 3R milestones after differential verification (ADR 0032, Migration model). There is one product: Siralos.

**R12 Verified has exactly two outcomes**, both require evidence — there is no silent or implicit retirement:

- **Retirement** — the TypeScript source under `packages/**` + `apps/**` is eligible for archival or removal, and `docs/development/RUST_MIGRATION.md` records the retained audit artifacts.
- **Retention** — the TypeScript reference is retained alongside the Rust successor, with an **explicit evidence-backed retention disposition** that states why retirement was not taken and what would change it.

The same template distinguishes the two outcomes (section 1). Both outcomes advance status surfaces (section 2), both require the same R11 + Stage-4 guardrails (section 3), and both preserve invariants even after the TypeScript code path is gone.

### 1.2 What the disposition document must additionally state

One markdown file is the **disposition record**:

`docs/development/RUST_MIGRATION.md` — new section **R12 retirement or retention disposition** — containing:

- **Disposition verdict** — one of `retirement` or `retention` (no third value, no qualifier like partial retirement).
- **Evidence SHA** — the exact `R11` Verified commit SHA + the Tier-1 audit SHA + the corpus version or digest that the verdict rests on (e.g., corpus vN NNN files). For retention, also the TypeScript retained surface SHA at disposition time.
- **Rationale** — a short paragraph naming the concrete reason for the verdict (for retention: which surface or guarantee remains TypeScript-owned and why; for retirement: that every required surface is at parity and no blocking issue remains).

#### Retirement — additional required evidence (when retention is not chosen)

| Additional evidence                                                                                                                                                                                                                                           | Why                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Every required scenario in the final corpus is **applicable** + passing on every platform (no remaining required but not due surface)                                                                                                                         | No required observable remains un-paritied |
| Retained audit artifacts: the differential harness out directory, scenario digests, and the `stage4-entry-gate.md` 17 criteria (all PASS at Verdict time) are retained by SHA after the TypeScript source is archived — they remain the post-retirement proof | Verification does not vanish with the code |

After retirement, the Rust path is the **sole behavioral source of truth**; fixing a bug means fixing the Rust code. The TypeScript archive is historical, not executed.

#### Retention — explicit evidence-backed disposition (when retirement is not taken)

Retention is **not** doing nothing. It must file:

- **Retained surface list** — every TypeScript surface that remains the oracle after the disposition, with its **SHA at disposition time** (e.g., `packages/core/src/godot/**` at commit `abc`, or `packages/core/src/identity/**` if a Godot-free retention).
- **Retention reason** per surface — one typed reason: `unported-godot`, `unported-H1-identity`, `blocked-by-fail-closed-primitive`, `measured-performance-regression` (with `performance-baseline.md` citation), `staged-rework`, etc. — never TBD or free prose alone.
- **Re-evaluation trigger** — what would change the disposition (e.g., R8-R9 entry review will close Godot parity, directory-relative primitive lands in Stage 4.2). Without a trigger, a retention disposition is not evidence-backed.
- **Expiry or review date** — the next quarterly or milestone-bound review date at which the disposition is re-evaluated (e.g., Review at next Stage-4 entry re-evaluation or next quarter, whichever is first).
- **Status-surface note** — the disposition does not imply indefinite dual maintenance; a future milestone may revisit retirement without re-arguing the evidence package.

A retention disposition that lacks any of the five fields is **not evidence-backed** and fails the R12 gate.

### Who signs the disposition

- **Decision:** this template — no signature beyond the commit itself.
- **Disposition execution:** the **R12 commit author** signs the verdict by advancing all 7 surfaces atomically; the commit message is `docs: promote R12 to Verified — <retired or retained> (\\R12\\ + audit \\A\\ — corpus vN NNN)` with the 5-field block in the body.
- **Stage-4 entry sign-off:** after the disposition, the Stage-4 entry re-evaluation (see section 3 guardrail d) signs `stage4-entry-gate.md` 17 criteria all PASS goes to `PRE-STAGE-4 ASSURANCE: PASSED` — only then may Stage 4 execution begin. Neither the disposition commit nor the gate edit may be split into two commits to bypass the 17-criteria check.

No single-person approve R12 button exists — signature is the **Verified commit + the gate edit passing the full check on the same worktree**.
