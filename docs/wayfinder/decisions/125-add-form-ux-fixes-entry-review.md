# 125 — The Provider Add-Form UX Fixes Entry Review

Ticket [110](../tickets/110-add-form-ux-fixes.md) · entry review [103](103-siralos-tui-entry-review.md) · Map.

> **User-directed 2026-08-31 (session HITL).** Three add-form UX defects from live usage: URLs rejected (the Char handler must accept all printable chars including : and /), no visible cursor in form fields, and no Up/Down field navigation — all three fixed.

## 2. Fixes F1–F3 — as authorized

| ID  | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Evidence / note                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | URL ACCEPTANCE: the form's Char handler must accept ALL printable characters including `:` and `/` (the endpoint URL `https://...` needs both). Verify the handler doesn't filter or intercept `:` and `/` — if it does, fix it to accept every `KeyCode::Char` except control characters.                                                                                                                                                                                                                                           | `tui.rs` `handle_key` form `KeyCode::Char` `!c.is_control()` accepts `:`, `/`; test `url_acceptance_char_handler_includes_colon_slash`                                          |
| F2  | VISIBLE CURSOR: each form field renders a visible cursor indicator (a block character `█` or underscore at the end of the current input text) so the user can see where they are typing. The cursor is at the END of the input (append-only — consistent with the Backspace-only editing model).                                                                                                                                                                                                                                     | `tui.rs` `provider_add_form_lines` appends `█` at end of active field; test `cursor_renders_in_form_field`                                                                      |
| F3  | UP/DOWN FIELD NAVIGATION: Up returns to the PREVIOUS field (restoring its validated value for editing — the field's already-validated value is placed in the input buffer for re-editing); Down advances to the NEXT field if the current field's input validates (same validation as Enter); if validation fails, the error is shown and Down is a no-op. The form's field order is Provider -> Model -> CredentialEnv -> Endpoint; Up at Provider is a no-op; Down at Endpoint is the same as Enter (completes the form if valid). | `tui.rs` `handle_key` form `KeyCode::Up`/`Down` with validation + restore; tests `up_returns_to_previous_field`, `down_advances_with_validation`, `full_form_flow_with_up_down` |
