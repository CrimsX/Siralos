# 100 — Activation B4: The Live Audit Surface

Governing plan 68 · entry review [95](95-context-activation-entry-review.md) · Map.

> **User-directed 2026-08-31 (session HITL).** B4 of the approved activation arc: the decision 91 ring and counters become the live audit trail for opted-in sessions — the /context render gains a bounded trailing audit segment (counters in pinned order, the last 8 tick records oldest-first) only when the subsystem is opted in and built; OFF is byte-transparent; the segment flows through the terminal sanitizer like every rendered line; nothing persists and no new commands exist. The activation arc (B1-B4) is complete pending its roll-up record.

## 2. Design — R1–R6 + bounded-shape pins (pre-committed)

| #                               | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Detail |

| R1 SURFACE                      | Bounded trailing audit segment inside `/context` only when the applied profile has `[profile.context_system].enabled = true` AND the subsystem built successfully. The existing `/context` render gains (a) counters block — each saturating `u64` counter in pinned declaration order with its name and value; (b) ring block — the LAST 8 tick records from the 64-record ring, oldest-first, one bounded line per record (tick `now`, canonical event count, events dropped, tier counts, assembled unique total, demotion counts, promotion count) using the record's existing field names. No new commands; no other output changes. `crates/siralos-cli/src/output.rs` `format_context_audit` (pure function of `ContextMetrics`) + `crates/siralos-cli/src/interactive.rs` `/context` seam (gated on `context_system_enabled && session.is_some()`). | R1     |
| R2 OFF TRANSPARENCY             | Absent key, `enabled=false`, or a failed build -> the `/context` render is byte-identical to pre-B4 behavior (no audit segment, no placeholder) — test-pinned. | R3 DETERMINISM                  | The audit segment is a pure function of the in-memory ring + counters; identical state -> identical bytes. `ContextMetrics` is deterministic from `TickInput` + tick output; `format_context_audit` is pure with no I/O, no threads, no hidden state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | R3     |
| R4 SANITIZER                    | The audit segment flows through the existing terminal sanitizer path like every other rendered line (single output boundary — no raw bypass). | R5 NO PERSISTENCE / NO MUTATION | The render is read-only over the ring; nothing is written or drained (drain semantics untouched). `format_context_audit` borrows `&ContextMetrics` immutably; `drive_tick` alone mutates metrics, never the render. | R6 BOUNDED                      | The segment is bounded by construction (8 records, fixed per-record line shape, pinned counter order) — no unbounded output. Counters: 12 lines fixed.
