# The Verbatim Credential and the Protocol Picker

Ticket [116](../tickets/116-api-key-marker-protocol-picker.md) · entry review [137](137-marker-protocol-entry-review.md) · [Map](../siralos-roadmap.md)

> **User-directed 2026-08-31 (session HITL, amended in place before commit).** The api key field stores what the user types VERBATIM — the form is an interface, not a validator: input starting with env: is stored as the env-var form, any other non-empty input is stored as the literal key (key:<value>), empty means no credential. The user has explicitly overridden the env-only-only posture for direct storage (the config is gitignored); env-only remains available via the env: prefix; display surfaces redact key: values; the secret-hygiene gate still guards repo files. Additionally: the model picker gains a sliding viewport (the selection is always visible), and provider errors render honestly and bounded (the effective URL + status + a truncated body, no raw HTML dumps). The api protocol remains a selectable picker over openai-completions (POST chat/completions, messages[], Bearer), openai-responses (POST responses, input/instructions, output Items), anthropic-messages (POST v1/messages, top-level system, required max_tokens, x-api-key + anthropic-version), with the legacy aliases accepted in the parse; the request-shaping use remains future work.
