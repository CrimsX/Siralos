## 2. Scoring table (S1–S5) + re-measurement rule

### Scoring table (implement exactly)

**S1 STOPWORDS:** a closed list, pinned in the decision: `["a","an","and","are","as","at","by","for","from","in","is","of","on","or","the","to","with"]`. Query terms that appear in the list (exact, case-insensitive) are dropped before matching. A query whose terms are ALL stopwords matches nothing (empty result) — honest and deterministic.

**S2 SCORE per node** = sum over non-stopword query terms of: whole-word occurrence in the node summary +10, else substring occurrence in the summary +3, plus: whole-word occurrence in the node_id +4, else substring occurrence in the node_id +1; PLUS tier bonus: HOT +8, WARM +4, COLD/ARCHIVE/none +0; PLUS kind weight: Knowledge +3, Source +1, all other kinds +0.

**S3 HIT CRITERION UNCHANGED:** a node is a hit iff some non-stopword term occurs (substring) in its summary or id — the scoring only re-RANKs (and stopword filtering narrows terms). No new fields are searched.

**S4 ORDERING:** hits ordered by score descending, tie-break node_id ascending (the canonical tiebreak). The result carries the integer score per hit (observability; deterministic).

**S5 READ-ONLY:** scoring reads the immutable snapshot only (summary, id, tier, kind). Tools stay read-only; the model cannot influence scores beyond the query terms.

### Re-measurement rule (pin verbatim)

"The decision 87 GO rule (recall parity, paged*2 < DeepAll, dedup guard, 9-cell sweep) and the decision 88 adoption rule are re-applied UNCHANGED to the numbers measured after the re-rank. The fixtures, strategies, estimator, and all thresholds are unchanged; only the search ordering that feeds the flows changes. Decisions 87 and 88 stand as recorded; decision 92 records the re-measured verdicts."
