# 102 — The Provider-Interface Takeaways

Governing plan 68 · entry review [79](79-context-management-foundations.md) · Map.

> **User-directed 2026-08-31 (session HITL).** A deep dive through the Meta Model API documentation (dev.meta.ai — the external-model family docs) discussed externally produced two actionable measurement takeaways and a set of explicitly refused ones: the cache-stability rule is pre-committed (never reorder or freeze assembly for cache hits), provider usage capture and the e1 informational comparison are implemented as measurement machinery under the decision 94 rule, and deferred tool loading, reasoning-effort, and schema-constrained completions are recorded as future additive tickets only.

## 4. Result

The comparison machinery is complete and unit-proven; real-usage evidence awaits a live recorded session with a provider that reports usage. The recorded response bodies in the existing fixtures do not contain `usage` objects, so the e1 informational table has no real measured rows to report. Decision 94's informational status is unchanged, and the e1 evidence is recorded as prerequisite material for any future estimator-range argument. No scheduler, assembly, tool, or benchmark change was made; the cache-stability rule is pre-committed as measurement-only; the recording format change is backward-compatible (v1 for absent usage, v2 for present) and left the corpus at v75.
