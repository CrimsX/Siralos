# Decision 86 — The V3 Heterogeneous Re-Gate

**Governing plan:** [68 — Real Provider Credentials and Registry](68-real-provider-credentials-and-registry.md) · **Entry review:** [79](79-context-management-foundations.md) · **Map:** [Siralos Roadmap](../siralos-roadmap.md)

> **User-directed 2026-08-31 (session HITL).** The v2 GO was challenged as fixture-driven: byte-identical filler inflates dedup savings and planted keys make recall un-failable. V3 rebuilds the fixtures realistically (distinct domain excerpts, multi-token queries, distractors, one intentional duplicate) and hardens the gate (savings decomposition, dedup-share guard, 9-cell estimator sweep) BEFORE the run. Only the fixtures and the gate hardening vary; runtime code is untouched.

## 2. Methodology

| Aspect                   | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixture realism          | Six gate scenarios (4 narrow `narrow-alpha/beta/gamma/delta`, 1 medium `medium-echo`, 1 broad `broad-foxtrot` — same names) + 1 informational `paraphrase-gap` EXCLUDED from aggregate. Every node's content per level is DISTINCT hand-written Siralos-domain prose (checkpoint pruning, differential audit, provider credentials, workspace revisions, lockfile verification, scene mutation, projection, tool loop). Lengths: summaries 100–400 B, structured 200–800 B, detailed 600–2000 B, source 1500–4000 B; identity = digest hex (64 B). NO repeated-char filler. Exactly ONE intentional duplicate pair (Source + Knowledge share identical L0 bytes in `narrow-alpha`). Queries 2–3 tokens (`checkpoint pruning`, `differential audit`, `provider credentials`, `workspace revisions`, `lockfile verification`, `scene projection`); key summaries contain ≥2 query tokens (pass threshold 2); each gated scenario with hits has 1–2 distractors whose summaries contain exactly ONE query token (distractor hit via substring `prunings` contains `pruning` but token `prunings` ≠ `pruning` → overlap 1, filtered by rerank). `broad-foxtrot` 5/6 nodes match with 2-token overlap (all pass) — paging cannot win on selectivity, only via dedup/level. Scheduler `token_estimate` = `estimate_tokens(summary.len()+digest.len())`. All digests distinct except declared duplicate. |
| Decomposition            | Per scenario & aggregate (integers, external-model's order): `dedup_saved = cost_no_dedup − actual` (flow with dedup disabled minus actual); `rerank_saved = cost_all_hits_with_dedup − actual` (expand-all-hits with dedup minus actual); `level_saved = total_saved − dedup_saved − rerank_saved` (residual equals sum `deepest_available − actual_chosen` by construction, ensures `dedup+rerank+level == total`). `total_saved = baseline − actual` (saturating). `dedup_share_bps = dedup_saved*10000/total_saved`, `dedup_guard_ok = total==0 \|\| dedup*2 ≤ total`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Dedup-share guard        | Pre-committed: if `total_saved>0 && dedup_saved*2 > total_saved` ⇒ verdict **NO-GO** regardless of percentage (win must be selective retrieval, not duplicate elimination).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 9-cell estimator sweep   | Recompute full accounting under `bytes_per_token ∈ {3,4,5} × tool_call_overhead ∈ {0,8,16}` (9 cells). GO requires `recall_ok && margin_ok && dedup_ok` in **ALL 9 cells**. Report cell table.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Informational paraphrase | `paraphrase-gap`: query `commit gating` vs key summary about `check-in approval rules…` (shares NO token, overlap 0, `inHits=false`). Excluded from aggregate; recorded as `informational.paraphraseGap {queryTokens, keyOverlapCount, inHits}`. Demonstrates frozen clause (d) lexical-only routing cannot find paraphrased relevance — documented tradeoff, not a failure.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Frozen                   | 50% bar, recall definition (`total_recall_paged == total_recall_baseline`), baseline definition (sum Identity), both strategies (`ExhaustiveV1`, `ProgressiveV2`) unchanged from decisions 83/85. No runtime file changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## 4. Result

V3 measured **NO-GO** (baseline 2286 vs paged 3012: recall 14/14, reduction −31.7% vs 50% bar, dedup share 0% of savings (0/0), 9/9 cells fail margin — 0/9 pass). The decision 85 GO does not survive honest fixtures; the audit and hygiene-metrics seam returns to gated status.
