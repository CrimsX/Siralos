# 107 — TUI T3: The Context Pane

Ticket [103](../tickets/103-siralos-tui.md) · entry review [103](103-siralos-tui-entry-review.md) · Map.

> **User-directed 2026-08-31 (session HITL).** T3 of the approved TUI arc: the decision 100 audit and tool activity render as a live right-hand pane for opted-in sessions — single-sourced from the same ContextMetrics the /context segment uses, byte-transparent when the subsystem is off, bounded by construction, sanitizer-disciplined; the consolidation ledger continues.

## 2. Design (P1–P7 + layout pins) — as implemented

| ID  | Design                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Evidence / note                                                                                                                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | GATING: the pane appears ONLY when the applied profile has `[profile.context_system].enabled = true` AND the subsystem built successfully — the same gating as the decision 100 `/context` segment, now one shared helper (`interactive.rs` `context_audit_session`) that the stdio `/context` arm, the TUI `/context` arm, and the pane builder all call. OFF (`!enabled` or no built session) returns `None`: the frame is byte-identical to T2's (transcript full width, no pane, no placeholder) — the OFF branch reuses the exact T2 flat layout.                                                                                                                                                                                                                                                           | `tui.rs` `build_context_pane`; `interactive.rs` `context_audit_session`; `off_byte_identical_frame_no_pane_no_placeholder`                                                                                              |
| P2  | LAYOUT: when active, a right-hand pane of fixed 40 columns (`CONTEXT_PANE_WIDTH`); transcript + input shrink to the remaining width; the status line stays full width; `ratatui` layout handles resize. The pane contains, top to bottom: the counters block (the SAME 12 counters in the SAME pinned order as the decision 100 segment, `CONTEXT_COUNTER_ORDER`), the ring block (the LAST 8 tick records, oldest-first, one bounded line each, the same field names as decision 100 R1b via `format_tick_record_line`), and the tool activity block (the last 8 tool rounds from host-observed history — tool name + result status, one bounded line each, oldest-first). Empty ring/activity renders the block header with no lines. Every pane line is truncated to the pane inner width on a char boundary. | `tui.rs` `draw_with_pane`, `context_pane_lines`, `CONTEXT_PANE_WIDTH`, `CONTEXT_PANE_RING_LIMIT`, `CONTEXT_PANE_ACTIVITY_LIMIT`; modal backdrop covers the whole body when the pane is present                          |
| P3  | SINGLE SOURCE: the pane data derives from the SAME `ContextMetrics` / host-observed history the `/context` audit uses — `context_counters` reads the same metrics fields in the pinned order, `context_ring_tail` slices the same ring with the same `saturating_sub(8)` window, `format_tick_record_line` uses the same field names, and `tool_activity_from_history` collects `ToolResult` items from the authoritative `application.history()`. No parallel extraction, no re-derived field logic.                                                                                                                                                                                                                                                                                                            | `pane_counters_match_audit_segment_in_pinned_order` (each pane counter present verbatim in the audit segment); `pane_ring_renders_last_8_oldest_first_after_10_ticks` (full pane ring lines equal the audit ring lines) |
| P4  | SANITIZER: every pane line's content passes the same sanitization the `/context` segment applies — counters and ring lines are host-side numbers plus static vocabulary (sanitizer-clean by construction); tool names pass through `sanitize_for_display` at extraction and statuses are the static typed `status_str` vocabulary. The pane introduces no new unsanitized source; the transcript sink path is untouched.                                                                                                                                                                                                                                                                                                                                                                                         | `tui.rs` `tool_activity_from_history`; sanitizer boundary intact, `cargo clippy --workspace --all-targets --all-features -- -D warnings` clean                                                                          |
| P5  | DETERMINISM: same state + viewport → byte-identical frame (TestBackend). The pane snapshot is an owned read-only clone rebuilt per redraw; `context_pane_lines` is a pure function of the snapshot and the inner width; no I/O, no threads, no hidden state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | `pane_determinism_byte_equal`                                                                                                                                                                                           |
| P6  | CONSOLIDATION (continues): whatever the pane work naturally touches of the still-duplicated dispatch (per the decision 106 ledger) gets consolidated — the audit/pane gating is now the single shared `context_audit_session` helper (this also fixes the TUI `/context` arm's holder-only check to the stdio arm's flag+holder check), and the TUI loop threads the `context_system_enabled` flag the TUI arm was missing. The updated ledger is recorded honestly below.                                                                                                                                                                                                                                                                                                                                       | `pane_gating_matches_audit_gating_consolidation_proof` (pane and audit gates agree on all four enabled×present combinations); ledger in §3                                                                              |
| P7  | NO PERSISTENCE / NO NEW COMMANDS: the pane is read-only over in-memory state — `build_context_pane` borrows metrics and history immutably, never drains or clears; every redraw rebuilds the snapshot so a tick is reflected in the next frame. No filesystem, no persistence, no new commands.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `pane_updates_reflect_tick` (read-only snapshot before/after a tick; frames differ)                                                                                                                                     |
