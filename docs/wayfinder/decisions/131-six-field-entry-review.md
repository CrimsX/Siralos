# 131 — The Six-Field Provider Form Entry Review

Ticket [113](../tickets/113-six-field-provider-form.md) · entry review [103](103-siralos-tui-entry-review.md) · Map.

> **User-directed 2026-08-31 (session HITL).** The add-form restructured to six fields in the user's exact order — url, api key (the env-var NAME per the standing env-only credential policy), display name, api protocol, model, model display name — with no examples in the labels, and the /models fetch wired into the form: after url + api key the model list auto-fetches and a picker (arrow navigation, Enter selects) replaces free-text entry, falling back to free text with an honest note when the fetch fails. Two additive profile keys: protocol (closed set, default openai-compatible) and model display name (shown in the header/status instead of the raw model id); both absent-transparent in the parse per the decision 54 precedent; the protocol's request-shaping use is future work recorded in the decision.
